# Intake, depth and action boundaries

## Loading boundary

Use this module when brief depth, unanswered requirements or an action boundary needs clarification. The entry skill already defines the compact opening; do not reload this file merely to repeat that overview. Read only the relevant heading. Economics, detailed preflight and downstream creative modules are conditional reads, not a startup bundle.

## First exchange

Extract what is already known. First show the Director's Project Guideline, then begin Step 1. If starting from very little, the guideline may be a short provisional goal and route with unknowns; do not invent specifics. Ask what the video should achieve, where/for whom it will run, and the desired production depth only if missing and consequential. Then resolve duration, tools and budget as needed. Do not ask for a camera model before knowing whether anything will be filmed.

## Guideline first, then numbered work

When a reusable written intake artifact is requested, use the [project brief template](../assets/video-project-brief.md). Complete only useful fields from accepted facts; it is optional and does not replace the concise opening.

Present the guideline in user-facing language: intended result and camera experience; constraints/fidelity; proposed look and sound; asset/reference gaps; tool choice and tradeoff; stage outputs; acceptance checks. Include background music as selected, proposed, deliberately absent or unresolved, plus dialogue/voiceover language and pronunciation needs. It is a director's plan derived from the prompt, not a questionnaire for the user to fill.

Then start **Step 1 — Brief and reference check**. Reuse known answers, inspect supplied assets, identify missing evidence and request only the inputs that matter next. A reference request should say which view/clip/detail is needed, why, what it will control and whether public research or a labeled approximation is an alternative. Never pretend a reference exists or silently replace a real-location reference with generated imagery. See [reference acquisition](visual-development.md#reference-acquisition-before-dependent-prompts).

Before Step 1, include the concise [model/effort and conversation card](model-and-context.md#opening-recommendation-and-stage-updates) in the guideline/director overview. State a currently available recommendation and reason, whether the setting is verified active, the continue/compact/fresh-task recommendation, and the cost/cache evidence or uncertainty. This is the same opening overview, not a second ceremony. Update it only when the stage or evidence changes. Recommend sensible defaults without requiring the user to become a pricing expert.

If images or videos will be generated, include the [three-option credit comparison](efficiency.md#three-generation-credit-options), separating image and video costs and recommending one route for each needed operation. State what each option costs and changes, with quote evidence or explicit preliminary assumptions. Do not invent a quote before scope/settings are known. Refresh the concrete charge before submission within the existing spending authorization.

Review each answer with [director preflight](director-preflight.md): reconcile it with accepted choices and actual references, flag consequential gaps or contradictions, explain the possible defect and recommend a specific resolution. Clarify direction relative to subject/camera/screen when it affects the shot. Enforce the affected action boundary without blocking unrelated preparation or repeatedly asking settled questions.

Typical sequence, adapted to actual work:

1. Brief and reference check.
2. Script, performance and audio plan, including timed dialogue and music intent.
3. Character/product/location reference development and look review.
4. Storyboard or camera-motion preview, with speech/turn timing.
5. Production with supported inputs, readiness evidence and existing sufficient authorization.
6. Edit, mix, color, full audiovisual review and delivery.

Steps may overlap, combine or be omitted when irrelevant; for existing footage start with the appropriate edit workflow after Step 1. Say what the current step produces and how it will be checked. Author the actual asset/shot/audio prompts yourself; the user supplies creative decisions and unavailable reference material, not a completed engineering form. Review a concrete result before dependent production; do not insert approval-only turns when choices are already delegated.

Field names shared with the brief: `project`, `purpose`, `format`, `audience`, `platform`, `runtime`, `complexity`, `stage`, `tools`, `constraints`, `budget`, `deadline`, `deliverables`, `style`, `story`, `characters`, `environments`, `camera`, `audio`, `captions`, `continuity`, `delivery`, `custom`.

Keep a value's origin: user instruction, supplied asset, proposed default, accepted recommendation or verified technical requirement. Distinguish agreed decisions from drafts. Do not claim the user approved a recommendation merely because it was offered.

For “vlog”, “filming herself”, “POV” or footage associated with a handheld/action camera, identify whether the audience sees that camera's recording or an observer filming its operator. Resolve ambiguity that would change the shot before producing the hero frame. Use the user's explicit viewpoint when already supplied; do not ask again. Apply [production readiness](production-readiness.md) to realism/accuracy requirements and changes following a failed test.

## Complexity

| Level | Choose when | Normal output |
|---|---|---|
| Quick | Few dependencies, simple action, low identity/geometry burden | Compact brief, short script/beat plan, minimal shot prompts, finishing notes |
| Standard | Several scenes, product or character continuity, spoken audio or alternate versions | Script, selected design references, shot table, continuity notes, edit/audio/delivery plan |
| Detailed | Interacting characters, complex motion, reusable 3D, strict brand accuracy, multiple locations or technical delivery | Treatment, asset/reference package, storyboard/animatic, dependencies, per-shot specifications and finishing handoffs |

Upgrade only the complicated part. A quick ad may need detailed product references but no character development. An hour-long lecture may need excellent sound, chapters and slides without elaborate cinematography. Explain extra work before expanding the requested scope.

## Requirements by next action

`REQUIRED` means the affected action cannot be done reliably without the information. It can be resolved by an explicit user value, established context, or a sensible clearly stated assumption when the decision is reversible. Do not assume spending permission, identity choices contrary to instructions, exact claims, or rights to unavailable assets.

| Action | Required before this action | Conditional requirement |
|---|---|---|
| Draft concept | Purpose/message and intended format/viewer sufficiently clear | Factual source if the concept rests on a consequential real claim |
| Draft script | Approximate runtime, premise/subject and narration/dialogue language if used | Exact mandatory copy, brand restrictions, story canon, teaching accuracy |
| Produce continuity-dependent assets | Defined subject/style and acceptance criteria | Accepted identity/product/environment reference or an authorized step to develop it |
| Generate video | Shot action, image source/operator and orientation states, duration, aspect, reference roles, audio intent, supported model/settings | Applicable readiness evidence: character views, geography/product control, pronunciation/timing, playback/listening route; confirmed access, fresh cost and sufficient authorization |
| Build/render 3D | Scene scale, framing, motion/timing, output use and chosen application | Real dimensions/geometry where precision matters; hardware feasibility for requested settings |
| Edit | Usable media or a clearly labeled placeholder edit; target runtime/aspect/timebase | Dialogue transcript, exact overlays, asset rights where release depends on them |
| Export | Exact dimensions, frame rate, codec/container supported by chosen tools, audio/caption variant and destination | Alpha/color-space handoff, delivery specification, commercial use restrictions, platform disclosure rules if applicable |
| Publish | Finished file, destination/account and publication authorization | Final copy, schedule, required disclosures and rights clearance for the actual assets |

Unknown information blocks only its dependent work. If a 9:16 deliverable is known but pixel dimensions are not, propose 1080 x 1920 for a review draft; verify final destination needs before export. This is a working default, not a universal platform specification.

## Handling user shortcuts

- `recommend` / `default`: choose a fit, explain its consequence briefly, record the assumption; proceed on reversible planning.
- `skip`: omit optional work. If required later, record the affected action instead of asking again immediately.
- `later`: keep a short open item with its due stage.
- `not applicable`: remove the branch if genuinely irrelevant. Silent graphics need no voice casting.
- `custom`: add a constraint under the relevant module; if it overrides an earlier decision, record what dependent work changes.

Example: "Skip storyboarding" can mean a compact shot list is sufficient. For an expensive multi-scene sequence, suggest a rough animatic because it tests timing before generation; do not insist on illustrated boards solely because Detailed mode was selected.

## Stages and review

Planning -> preproduction -> production -> finishing -> delivery. Move between stages as the task requires; permit starting with existing footage. At a creative review point, show a concrete draft, one recommendation and only consequential alternatives. If the user has delegated those choices, proceed within that delegation. Existing authorization survives routine revisions within its scope.

For budget, separate planning estimate, authorized spend, currency/provider credits and retry limits. `Budget: recommend` authorizes a recommendation, not a charge. Reuse the cost-aware-media workflow when production becomes relevant.
