# Precision actions and contact

Load when success depends on touching the exact control, using a mechanism, removing an attached prop or making a precise handoff. Ordinary gestures do not need this record.

## Establish the target

Keep the clean authoritative object image and a separate marked explanatory copy. Identify the object/version, target feature and its position in object coordinates; screen left alone becomes ambiguous after a rotation, crop or mirror. Record those transforms, or mark the corresponding target again on the actual input. Prefer a pointer beside the feature to a mark that obscures its shape. For a real product, verify the mechanism using the correct model's documentation or demonstrated operation; an arrow establishes a target, not how it works.

Use the annotation for planning first. Translate it into clear spatial language and the selected tool's supported controls. Attach a marked image only when appropriate to that input mode, identify its limited role and check for marks leaking into the output. A filename in prose does not bind either reference.

## Describe the causal action

Use only the needed fields: `object/version | clean/marked sources | target | supporting hand | acting hand/finger | approach -> contact -> travel -> release | visible result | start/end state`.

Separate the hand that supports the object from the one that acts. Check reach, grip, occupied fingers, material deformation and time for repositioning. A press, slide, twist and peel are different mechanisms. For a removable disguise, specify the attached prop and its edge, detachment and destination; do not ask biological hair to vanish. For a key handoff, show recipient contact before the giver releases it. For a tossed cap, track release, travel, landing and the settled prop so it cannot simply disappear.

Example to adapt: support the remote in the left palm; the left thumb approaches the upper half of the verified channel rocker, presses once and releases; the navigation ring remains untouched. The selected channel changes only after the press. Preserve shell, grip and labels; the delivered image has no annotation.

## Review and repair

Watch approach, contact, travel, release and response in motion. Check the exact feature, plausible hand/object interaction, stable geometry and count, correct causal order, and absence of marks. A correct end frame does not prove a correct operation. If a necessary feature is hidden, use a revealing angle or insert. For strict operation that generation cannot hold, compare real footage, controlled animation or a scoped composite through the [repair decision](repair-cards.md#director-repair-decision). Do not repeat the same ambiguous prompt with stronger adjectives.
