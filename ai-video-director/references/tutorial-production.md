# Tutorial steps 5–6: production, repair and finishing

Read only the current step; load repair/comparison detail only if that branch becomes relevant.

## Step 5: Make the selected shots

**Teach:** the project brief becomes asset prompts, shot prompts, actual tool inputs/settings and finishing instructions. A long generic prompt does not replace references or a supported control.

**Guide:** write prompts from the accepted camera/character/location/action/audio decisions using [shots and prompts](shots-prompts.md). Explain the few clauses that control this shot. Bind references through the tool's actual input fields. In practice mode, stop at the usable prompt/settings plan unless real execution is requested.

For execution, verify readiness and supported settings, inspect existing job/retry state, get a fresh quote where needed and use existing sufficient authorization. If paid permission is missing, prepare the exact proposed run first. Review one meaningful result before broad production; no unbounded retries or spending for the sake of a lesson.

**Small result:** actual media plus a status record, or a clearly labeled unexecuted handoff. Look for failures across the whole clip, not just its opening frame. If a trial fails, use the [repair decision](repair-cards.md#director-repair-decision) and matching defect card: show the defect, explain possible causes, compare actual repair, re-edit and regeneration, then recommend one route with cost evidence and what must remain unchanged. Ask the learner for a creative choice only when needed; do not ask them to diagnose the model unaided. Verify the repaired property and previously passing criteria before proceeding.

**Conditional repair lesson:** when a defect appears, teach one concrete example, such as a sign changing after a pedestrian passes. Explain that tracking new lettering repairs the pixels, while a cutaway hides the error. Show the compact comparison and explain why the recommended route fits this footage; label infeasible routes and unknown prices. Offer one unresolved choice with a recommendation, such as preserving a continuous take through compositing versus permitting a cutaway. Reuse an already accepted choice. Only then load the selected editor adapter and guide a small difficult interval through repair and playback review. Practice mode may use a clearly hypothetical example without generating media or claiming a completed repair. This lesson does not automatically spend credits, launch all three routes or load both editors.

**Optional comparison exercise:** only if the learner requests it or a recurring failure justifies a bounded test, load [comparative tests](comparative-tests.md). In planning practice, compare two written prompts and identify one changed variable; clearly say that this does not test rendered quality. Actual media A/B tests need a selected scope, adequate review and existing sufficient budget; never spend twice merely to teach comparison.

## Step 6: Finish, review and learn from the result

**Guide:** use the selected editor to assemble, trim, mix sound, match color, add requested captions and export. Load [edit and motion](edit-motion.md), [audio](audio-captions.md) and [delivery](delivery.md) only for the relevant work.

Review the whole video with sound, then inspect difficult frames/transitions. Check viewpoint, character/product identity, contact/gait, stable geography/signs, dialogue pronunciation and lip-sync, music masking/cues, ambience continuity and technical specs. Screenshots/transcripts cannot certify the unheard/unwatched properties. Use a capable reviewer when necessary; mark failed and unverified criteria honestly. A newly found defect follows the conditional repair lesson above; reuse its saved decision if already resolved rather than restarting the lesson.

**Small result:** the reviewed export and editable source if requested, or the completed practice plan. End with the files/links, what was actually made, remaining defects and a short explanation of why the chosen tools helped. Offer one optional next learning exercise instead of automatically starting another project.
